# DorokeiGame ― OP・運営ガイド { .page-op #dorokei-op }

DorokeiGame の導入・ロビー／エリア設定・config・権限・管理コマンドをまとめます。

## 基本情報

| 項目 | 値 |
|---|---|
| プラグイン名 | DorokeiGame |
| バージョン | 3.0 |
| api-version | 26.1.2 |
| 作者 | へんりー |
| メインコマンド | `/dorokei`（エイリアス `/dk`） |
| 依存プラグイン | なし |
| 設定ファイル | `plugins/DorokeiGame/config.yml` |

!!! warning "実装状況：Phase 1-2"
    現在は **ロビーシステム＋ログアウト処理** までの実装段階です。ロビー参加・看板連携・自動警官割り振り・追跡演出・捕獲／救出・自動ロビー再参加は動作します。旧方式のコマンド（後方互換）も残っていますが、運用ではロビー方式を推奨します。詳細は下記「実装状況」の節を確認してください。

## 導入手順

1. ビルドした `DorokeiGame` の jar ファイルをサーバーの `plugins/` フォルダに配置する。
2. サーバーを起動・再起動すると `plugins/DorokeiGame/config.yml` が自動生成される。
3. 後述の手順でロビーとゲームエリアを設定する。
4. 必要に応じて `config.yml` を直接編集し、サーバーを再起動して反映する。

!!! note "config の反映について"
    本プラグインには config 再読み込み用のコマンドがありません。`config.yml` を手で編集した場合は **サーバーの再起動** で反映してください。なお `/dorokei setup ...` 系コマンドで変更した内容は即座にファイルへ保存され、ゲームへも反映されます。

## config.yml 設定項目

| キー | 既定値 | 説明 |
|---|---|---|
| `version` | "3.0" | 設定ファイルのバージョン |
| `spawn-location` | world / 0,64,0 | 初期リスポーン地点。ログアウト時に戻り先が不明な場合に使用 |
| `lobbies` | `{}` | ロビー定義。`/dorokei setup lobby` で追加される。各ロビーは `name` / `world` / `x` / `y` / `z` / `max-players`（既定20）/ `linked-area` を持つ |
| `game-areas` | `{}` | ゲームエリア定義。`/dorokei setup area` で追加される |
| `game-settings.game-time` | 480 | ゲーム時間（秒）。既定8分 |
| `game-settings.escape-preparation-time` | 30 | 逃走準備時間（秒）。この間は警官が動けない |
| `cop-allocation` | 2〜20の対応表 | プレイヤー数ごとの警官人数の割り振り表 |
| `defaults.cop-count` | 1 | 旧方式（後方互換）用の既定警官人数 |
| `defaults.game-time` | 300 | 旧方式（後方互換）用の既定ゲーム時間（秒） |

### 警官の自動割り振り（`cop-allocation`）

参加人数に応じて警官の人数を自動決定します。既定の対応表は次のとおりです。

| 参加人数 | 警官数 | 参加人数 | 警官数 |
|---|---|---|---|
| 2〜4人 | 1人 | 12〜14人 | 5人 |
| 5〜6人 | 2人 | 15〜17人 | 6人 |
| 7〜8人 | 3人 | 18〜20人 | 7人 |
| 9〜11人 | 4人 | | |

!!! tip "対応表にない人数のとき"
    `cop-allocation` に該当する人数の項目がない場合は、約35%を目安にした内部計算で警官数が決定されます。21人以上の場合も内部計算で7人になります。

## セットアップ手順

専用ワールドを用意し、OP権限で以下のコマンドを **設定したい地点に立って** 実行します（実行位置が座標として保存されます）。

```text
/dorokei setup spawn                       # 初期リスポーン地点
/dorokei setup lobby <ID> [名前]           # 待機ロビーを設定
/dorokei setup area <ID> pos1 [名前]       # ゲームエリアの角1（開始点）
/dorokei setup area <ID> pos2              # ゲームエリアの角2（終了点）
/dorokei setup area <ID> jail              # エリアの牢獄地点
/dorokei setup link <ロビーID> <エリアID>  # ロビーとエリアを紐付け
```

設定の流れは次のとおりです。

1. `/dorokei setup spawn` で初期リスポーン地点を設定する。
2. `/dorokei setup lobby lobby1 ドロケイ会場` のようにロビーを設定する（`/dorokei setup lobby` 経由で作成すると上限20人として登録されます。`config.yml` の `lobbies.<ID>.max-players` を手動で書き換えれば変更可能）。
3. `/dorokei setup area area1 pos1` → `pos2` → `jail` の順でゲームエリアを設定する。エリアは pos1・pos2・jail の3点がそろって初めて有効になります。
4. `/dorokei setup link lobby1 area1` でロビーとエリアを紐付ける。
5. `/dorokei list` でロビー・エリアが正しく登録されているか確認する。

!!! tip "看板の設置方法"
    プレイヤーがロビーへ参加するための看板を設置できます。
    - **参加看板** … 1行目に `[Dorokei]` または `[ドロケイ]`、2行目にロビーID を書く。
    - **退出看板** … 1行目に `[DorokeiLeave]` または `[ドロケイ退出]` を書く。
    設置に成功すると看板が自動で整形されます。

## ゲームの運営

1. プレイヤーが看板または `/dorokei join` でロビーに集まるのを待つ（最低2人必要）。
2. `/dorokei gamestart <ロビーID>` でゲームを開始する。コマンドブロックからの実行も想定されています。
3. ゲームは「カウントダウン → 逃走準備（既定30秒）→ 追跡開始 → 決着」と進行します。
4. 終了から5秒後に参加者は自動でロビーへ戻され、同じロビーへ再参加した状態になります。

## 管理コマンド

| コマンド | 説明 |
|---|---|
| `/dorokei`（引数なし） | ヘルプを表示する |
| `/dorokei list` | ロビー・ゲームエリアの一覧と状態を表示する |
| `/dorokei gamestart <ロビーID>` | 指定ロビーのゲームを開始する |
| `/dorokei setup spawn` | 初期リスポーン地点を設定する |
| `/dorokei setup lobby <ID> [名前]` | ロビーを設定する |
| `/dorokei setup area <ID> pos1\|pos2\|jail` | ゲームエリアの各地点を設定する |
| `/dorokei setup link <ロビーID> <エリアID>` | ロビーとエリアを紐付ける |

### 旧コマンド（後方互換）

旧方式のゲーム管理コマンドも残っています。ロビー方式への移行を推奨しますが、参考までに記載します。

| コマンド | 説明 |
|---|---|
| `/dorokei start` | 旧方式（全オンラインプレイヤー対象）でゲームを開始する |
| `/dorokei setpolice <人数>` | 旧方式の警官人数を設定する |
| `/dorokei settime <秒数>` | 旧方式のゲーム時間（秒）を設定する |
| `/dorokei setjail` | 旧方式の牢獄地点を設定する |

!!! note "plugin.yml の usage 表記について"
    `plugin.yml` の usage 欄は `/dorokei <start|setpolice|settime|setjail>` と古い旧コマンドのみの記載になっていますが、実際には `setup` / `gamestart` / `list` / `join` / `leave` のサブコマンドが実装されています。引数なしで `/dorokei` を実行すると最新のヘルプが表示されます。

## 権限ノード

`plugin.yml` に **permissions ブロックは定義されていません**。専用の権限ノードは存在せず、`/dorokei setup` 系のセットアップコマンドや `/dorokei gamestart` などはコマンド実行権限（既定で OP）で判定されます。

| 区分 | 判定 |
|---|---|
| `/dorokei`（全サブコマンド） | 専用権限ノードなし＝コマンド権限（既定で OP が実行可能） |

!!! note "プレイヤー操作について"
    `/dorokei join` / `leave` / `list` もコマンド権限で動作します。一般プレイヤーにロビー参加を許可する場合は、看板による参加導線を利用するか、サーバーの権限プラグインで `/dorokei` の実行を許可してください。

## 実装状況（Phase 1-2）

!!! info "実装済みの機能"
    - ロビーシステム（複数ロビー対応・既定上限20人・看板／コマンド参加）
    - ゲームエリア管理（pos1/pos2/jail の3点による範囲設定・エリア外移動制限）
    - 参加人数に応じた警官の自動割り振り（`cop-allocation`）
    - 逃走準備フェーズ（警官の盲目・移動制限）と追跡フェーズ
    - 捕獲（警棒）・牢獄・市民による救出（救出時の速度上昇バフ）
    - 警官／市民の専用アイテム（煙幕玉・ダッシュブーツ・スプリントブースト・ネット投擲）
    - ボスバー・**専用サイドバー（残り時間／逃走中／捕獲済／救出／役割）**・コンパス・追跡パーティクル・心臓の鼓動音などの演出
    - 勝敗判定（全市民捕獲／時間切れ／全員ログアウト）
    - ログアウト処理（ゲーム・ロビーからの離脱、次回ログイン時の位置復帰）
    - ゲーム終了後の自動ロビー帰還・再参加

!!! warning "注意点・制限"
    - 旧方式（`start` / `setpolice` / `settime` / `setjail`）のコマンドが後方互換として残っています。新方式のロビー運用と混在させないでください。
    - config 再読み込み用コマンドはありません。`config.yml` を手動編集した場合はサーバー再起動が必要です。
    - `plugin.yml` の usage 表記が実装と一致していません（上記の管理コマンドの節を参照）。

## トラブルシューティング

??? failure "ゲームが開始できない（プレイヤーが足りません）"
    ゲーム開始には **ロビーに最低2人** が必要です。`/dorokei list` でロビーの参加人数を確認してください。

??? failure "「ゲームエリアが設定されていません」と表示される"
    ロビーにエリアが紐付いていません。`/dorokei setup link <ロビーID> <エリアID>` で紐付けてください。エリア自体も pos1・pos2・jail の3点がそろっていないと有効になりません。

??? failure "ロビーやエリアが list に表示されない"
    ロビーは座標が正しく保存されているか、エリアは pos1／pos2／jail の3点すべてが設定されているかを確認してください。3点がそろわないエリアは読み込まれません。ワールドが存在しない場合も読み込みに失敗します。

??? failure "参加看板をクリックしても参加できない"
    看板の1行目が `[ドロケイ]`、2行目に有効なロビーID が入っているか確認してください。対象ロビーがゲーム中の場合は参加できません。

??? failure "config.yml を編集したのに反映されない"
    config 再読み込みコマンドはありません。サーバーを再起動して反映してください。
