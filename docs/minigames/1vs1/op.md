# 1vs1 ― OP・運営ガイド { .page-op #pvp1vs1-op }

1vs1 の導入・地点設定・config・権限・管理コマンドをまとめます。


## 基本情報

| 項目 | 値 |
|---|---|
| プラグイン名 | 1vs1 |
| バージョン | 1.4 |
| api-version | 26.1.2 |
| メインコマンド | `/pvp`（エイリアス `/1v1`） |
| プレイヤー操作 | `/pvp <join\|leave\|spectate\|lobby\|bet\|start\|status\|solo\|ranking>`（全員可）または各看板の右クリック |
| 管理コマンド | `/pvp <stop\|setrank\|ranklist\|setspawn…\|setchest\|setsign…>` 等（OP / `1vs1.admin`） |
| 依存プラグイン | なし |
| 設定ファイル | `plugins/1vs1/config.yml`、`plugins/1vs1/ranks.yml` |

!!! note "データの保存について"
    プラグインは2つのファイルを使用します。`config.yml` には開始地点・チェスト位置が、`ranks.yml` には各プレイヤーのバトルパスランクが保存されます。`ranks.yml` はプラグイン有効化時に自動生成され、サーバー停止時に保存されます。

## 導入手順

1. ビルドした `1vs1` の jar ファイルをサーバーの `plugins/` フォルダに配置する。
2. サーバーを起動すると `plugins/1vs1/` フォルダと `config.yml`・`ranks.yml` が自動生成される。
3. 後述の「セットアップ手順」で開始地点とキットチェストを設定する。
4. 設定はコマンド実行時に即保存されます（手動での再読み込みコマンドはありません）。

## config.yml 設定項目

`config.yml` は初回起動時にテンプレートが生成され、各値はゲーム内コマンド（`/pvp setspawn <1\|2>`・`/pvp setchest`・`/pvp setsign`）の実行で書き込まれます。手動で編集する必要は基本的にありません。保存される構造は以下のとおりです。

| キー | 内容 |
|---|---|
| `points.point1.{world,x,y,z}` | プレイヤー1の対戦開始地点（`/pvp setspawn 1`） |
| `points.point2.{world,x,y,z}` | プレイヤー2の対戦開始地点（`/pvp setspawn 2`） |
| `points.chests` | 装備リセット用チェストの位置リスト（`{world,x,y,z}` の配列・複数可。`/pvp setchest` で追加） |
| `points.spectate.{world,x,y,z}` | 観戦場所（`/pvp setspectate` で設定） |
| `points.lobby.{world,x,y,z}` | ロビー（`/pvp setlobby` で設定） |
| `points.startspawn.{world,x,y,z}` | 初期スポーン地点＝離脱・試合終了時の戻り先（`/pvp setstartspawn` で設定。未設定時は試合開始前の位置に戻る） |
| `signs.join` | `[PvP参加]` 看板の位置リスト（`{world,x,y,z}` の配列） |
| `signs.leave` | `[PvP離脱]` 看板の位置リスト（右クリックで待機キューから離脱・入場料返金） |
| `signs.bet` | `[PvP賭け]` 看板の位置リスト |
| `signs.start` | `[PvP開始]` 看板の位置（識別子ごとのマップ。例 `signs.start.default: [ {world,x,y,z}, … ]`） |
| `signs.spectate` | `[PvP観戦]` 看板の位置リスト |
| `signs.lobby` | `[ロビー]` 看板の位置リスト |
| `signs.solo` | `[PvPソロ]` 看板の位置リスト（CPU道場の入口） |

!!! note "値はコマンドで設定します"
    座標は `/pvp setspawn <1\|2>`・`/pvp setchest`・`/pvp setsign` などのコマンドで設定するのが正しい手順です。コマンド実行時に `config.yml` へ自動保存されます。旧形式キー（`points.chest1`/`chest2`、識別子なしのフラットな `signs.start`）は起動時に自動で新形式へ移行されます。


### CPU道場（ソロ）の設定

`solo:` は動作の設定、`dojo-stages:` は段位の定義です。どちらもプラグイン更新時に **足りない項目だけ自動で追記** されます（設定済みの値は上書きしません）。`dojo-stages` は運営が自由に増減・並べ替えできるデータ扱いで、更新しても既定の段位に戻りません。

| キー | 既定 | 内容 |
|---|---|---|
| `solo.enabled` | true | false でソロを無効にする |
| `solo.menu-delay` | 3 | 挑戦が終わってからソロメニューを開くまで（秒） |
| `solo.countdown` | 3 | 1戦ごとの開始前カウントダウン（秒） |
| `solo.intermission` | 3 | 勝ってから次の段位が始まるまで（秒。この間は無敵） |
| `solo.fight-seconds` | 120 | 1戦の制限時間（秒）。時間切れは残り体力の割合で判定 |
| `solo.broadcast-result` | true | 挑戦の結果をサーバー全体に1行流す |
| `solo.ranking-size` | 10 | `/pvp ranking` の表示人数 |
| `solo.bot-name` | CPU | CPU の頭上の名前（「【初段】CPU」） |
| `solo.leash-radius` | 40 | CPU が開始地点2からこの距離より離れたら戻す |

`dojo-stages.<段位ID>` の項目（上から順に勝ち抜く。ID に `.` は使えません）：

| キー | 内容 |
|---|---|
| `display` / `icon` | 表示名／ソロメニューのアイコン |
| `entity` | CPU の Mob（`ZOMBIE`・`HUSK` など。Mob 以外は不可） |
| `head` | 頭に被せるプレイヤーヘッドの持ち主（Java 版の名前。空なら普通の頭。起動時に見た目を取得） |
| `health` / `damage` / `speed` | 体力／近接ダメージ（防具で減る前。鉄の剣のプレイヤー＝6）／移動速度（ゾンビ＝0.23） |
| `knockback-resistance` | ノックバック耐性（0〜1） |
| `equipment` | `chestplate`・`leggings`・`boots`・`weapon`（見た目と防御力。`NONE` で無し） |
| `block-chance` | 正面からの攻撃を盾で防ぐ確率（0〜1） |
| `bow-cooldown-ticks` / `bow-damage` | 離れたときに弓を撃つ間隔（0 で使わない）／弓のダメージ |
| `strafe` / `crit-chance` | 接近戦で左右に動く頻度／ジャンプ攻撃（1.5倍）の頻度（0〜1） |

!!! tip "強さの調整"
    既定値は目安です。実際に挑戦して、上の段位ほど勝率が下がるように `health`・`damage`・`speed` から調整してください。段位を足すときは、既存の段位をコピーして ID と `display` を変えるのが簡単です（ソロメニューに並ぶのは先頭9段位まで）。変更は再起動（またはプラグインの再読み込み）で反映されます。

記録は `plugins/1vs1/solo-records.yml` に保存されます（データ用ファイル。ConfigUpdater の対象外）。

## ゲーム仕様（OP向けの内部挙動）

運営時に把握しておくべき、ソース実装上の固定値・挙動です。

| 項目 | 仕様 |
|---|---|
| 初期バトルパスランク | R3（未登録プレイヤーのデフォルト） |
| ランクの範囲 | R1〜R10（範囲外は自動で丸められる） |
| 入場料 | ランク × 10 エメラルド |
| 待機キュー上限 | `max-members`（既定8。待機キュー＋試合中の合計。最小2）。1試合に出るのはキュー先頭の2人 |
| 勝利賞金（通常勝利） | 新ランク × 20 エメラルド、勝者ランク +1 |
| 勝利賞金（2ランク以上格上の勝利） | 現ランク × 12 エメラルド、ランク変化なし |
| 敗北時 | 敗者ランク −1 |
| 賭け配当倍率 | 同ランク2.0倍／格下は +0.1×ランク差／格上は −0.1×ランク差 |
| 賭け額 | GUIの固定ボタン 1／5／10／32／64 エメラルド（再賭けは上書き・前の賭け金は返却） |
| キットチェストのプリセット | 鉄一式（兜・胸・脚・靴）、盾、鉄の剣、焼き肉×64 |
| 看板の状態表示 | 2行目に「待機: N人」（キュー人数）「開始可能／人数不足」「対戦待ち／対戦中」等を自動表示・自動更新 |

!!! note "プリセットアイテムは固定です"
    試合終了時にキットチェストへ補充される装備セットはソース内に固定されており、config.yml では変更できません。

## 管理ツール（OP専用）

`/pvp wand` で管理ツール（ブレイズロッド「【1vs1】管理ツール」）を受け取り、右クリック（統合版はタップ/長押し）で管理メニューを開きます。`/pvp menu` でも開けます（参加中でも開けます）。メニューのボタンで `config.yml` の内容を直接変更でき、変更は即保存・すぐ反映されます。

- 数値：＋/−ボタンで変更（即保存）。名前に今の値と範囲が出ます
    - 参加の上限人数（3〜64）
    - CPU道場：1戦の制限時間（30〜600秒）・開始カウント（0〜10秒）・段位の合間（1〜10秒）・メニューを開くまで（0〜10秒）・CPUの行動範囲（10〜100ブロック）
    - ランキングの表示人数（3〜30）
- 切り替え：CPU道場の有効/無効・道場の結果を全体に流す・参加中の名前表示・参加通知・看板の蝋引き（統合版）・名前表示の色
- 地点：ボタンを押すと立ち位置に設定（ロビー／初期スポーン／観戦場所／開始地点1・2）。開始地点は、もう一方と向かい合う向きに自動でそろえます。「開始地点を光らせて確認」で位置を表示できます
- キットチェスト：チェストを見ながら（5ブロック以内）押すと登録／解除
- 看板：看板を見ながら（5ブロック以内）押すと参加／離脱／開始／賭け／観戦／ロビー／ソロ看板を登録、ハサミで登録解除。開始看板の識別子が複数あるときは選ぶ画面が出ます
- 試合のキット：「今の自分の持ち物をキットにする」で、防具・左手・インベントリの中身をそのまま `kit` に保存（種類と個数だけ。エンチャント・名前は保存されません）。「既定のキットに戻す」もあります（どちらも5秒以内に2回押し）
- CPU道場の段位：段位ごとに体力・攻撃力・速さ・ノックバック耐性・盾で防ぐ確率・弓の間隔/攻撃力・左右に動く頻度・ジャンプ攻撃の頻度を＋/−で変更。Mob（ゾンビ/ハスク/ドラウンド）・武器・胴/脚/足の防具は押すと切り替わります。アイコン（手に持っている物）・頭（自分のスキン/普通の頭）・並び順の変更、段位の追加（最後の段位をコピー）・削除（5秒以内に2回押し）もできます。CPU道場の挑戦中は変更できません。段位の表示名は `config.yml` の `display` で変えます
- 運用：対戦開始・設定状況・リロード・強制停止（強制停止は5秒以内に2回押し）
- 1vs1 に参加中（待機キュー・対戦中・CPU道場）は受け取れません（離脱してから実行）。捨てると消えるので再度 `/pvp wand` で取得してください。コンテナ・額縁・防具立てには入れられません
- 統合版：チェストGUIで操作できます。数値は左右クリックに頼らず＋/−の別ボタンで操作します

```text title="管理ツール（ブレイズロッド）を受け取る"
/pvp wand
```

```text title="管理メニューを開く"
/pvp menu
```

```text title="config.yml を読み直す（手で直したあとに）"
/pvp reload
```

## セットアップ手順

専用のPvPアリーナを用意し、OP権限で以下のコマンドを **その場に立って／チェストを見て** 実行します。

```text title="プレイヤー1の対戦開始地点（コマンドを実行した自分の現在地が保存される）"
/pvp setspawn 1
```

```text title="プレイヤー2の対戦開始地点（コマンドを実行した自分の現在地が保存される）"
/pvp setspawn 2
```

```text title="装備リセット用チェスト（視線の先5ブロック以内のチェストを登録。複数回実行で複数登録可・中身は共通プリセット）"
/pvp setchest
```

```text title="観戦場所（コマンドを実行した自分の現在地が保存される）"
/pvp setspectate
```

```text title="ロビー（コマンドを実行した自分の現在地が保存される）"
/pvp setlobby
```

```text title="初期スポーン地点（離脱・試合終了時の戻り先。コマンド実行者の現在地）"
/pvp setstartspawn
```

看板の登録は `/pvp setsign <種別>` で行います。**視線の先5ブロック以内の看板** を見ながら、登録したい種別のコマンドを実行してください。

```text title="参加看板 [PvP参加]（クリックで待機キューに参加）"
/pvp setsign join
```

```text title="離脱看板 [PvP離脱]（クリックで待機キューから離脱・入場料返金）"
/pvp setsign leave
```

```text title="賭け看板 [PvP賭け]（クリックで賭けGUIを開く）"
/pvp setsign bet
```

```text title="開始看板 [PvP開始]（クリックで試合開始。<識別子> は任意の文字列。例: default）"
/pvp setsign start <識別子>
```

```text title="観戦看板 [PvP観戦]（クリックで観戦場所へ）"
/pvp setsign spectate
```

```text title="ロビー看板 [ロビー]（クリックでロビーへ）"
/pvp setsign lobby
```

```text title="ソロ看板 [PvPソロ]（クリックでCPU道場に入りソロメニューを開く）"
/pvp setsign solo
```

```text title="視線の先5ブロック以内の看板の登録を解除"
/pvp setsign delete
```

- `setspawn 1`・`setspawn 2`・`setspectate`・`setlobby`・`setstartspawn` は **コマンド実行者の現在位置** を保存します。プレイヤーを飛ばしたい場所に立って実行してください。
- `setchest` は **視線の先5ブロック以内のチェスト** を対象にします。チェストを見ながら実行してください。チェスト以外を見ていると失敗します。複数回実行すると複数のチェストを登録でき、中身はすべて共通プリセットになります。
- `setsign <type>` は **視線の先5ブロック以内の看板** を対象にします。登録すると看板に1行目のタグ（`[PvP参加]` 等）・2行目の状態表示・3行目の案内が自動で書き込まれ、以降プレイヤーが右クリックで操作できるようになります。同じ看板を別タイプで登録し直すと、旧登録は自動で外れます。
- 開始看板は `/pvp setsign start <識別子>` のように **識別子** を付けて登録します。識別子ごとに複数登録できますが、キューは単一のため動作はどの開始看板でも共通です。
- 開始地点（point1・point2）が未設定だと `/pvp start` で試合を開始できません。
- 観戦場所・ロビーが未設定の場合、対応する看板を押したプレイヤーに「未設定」のエラーメッセージが表示されます。
- キットチェストは試合終了時にプリセット装備でリセットされます。未設定の場合はリセットがスキップされ、サーバーログに警告が出ます。

!!! tip "推奨セットアップ"
    開始地点2か所はアリーナ内の対角などに、キットチェストは各選手がすぐ装備を取れる位置に設置すると運営がスムーズです。`[PvP参加]`・`[PvP賭け]`・`[PvP開始]`・`[PvP観戦]`・`[ロビー]` の各種看板はロビーなどプレイヤーが集まる場所にまとめて設置すると遊びやすくなります。

## 管理コマンド

`/pvp`（エイリアス `/1v1`）のうち、**プレイヤー用（join/leave/spectate/lobby/bet/start/status/solo/ranking）は全員**、セットアップ・管理系は **OP（`1vs1.admin`）専用** です。

### プレイヤー用（全員可）

| コマンド | 説明 |
|---|---|
| `/pvp join` | 待機キューに参加する（`[PvP参加]` 看板と同じ） |
| `/pvp leave` | 待機キューから離脱する（入場料返金） |
| `/pvp bet` | 賭けGUIを開く |
| `/pvp spectate` | 観戦場所へ移動する |
| `/pvp lobby` | ロビーへ移動する |
| `/pvp start <識別子>` | 待機キューが2人そろっているとき試合を開始する（識別子は任意・省略可。コマンドブロック/コンソールからも実行可） |
| `/pvp status` | 現在の設定・ゲーム状態を確認する（読み取り専用。CPU道場の状況も表示） |
| `/pvp solo` | CPU道場（ソロ）に入ってソロメニューを開く（在籍中なら開き直す） |
| `/pvp solo start` | メニューを通さずに CPU道場の挑戦を始める |
| `/pvp ranking` | CPU道場のランキング上位と自分の順位 |

### 管理用（`1vs1.admin`）

| コマンド | 説明 |
|---|---|
| `/pvp wand` | 管理ツール（ブレイズロッド）を受け取る（右クリックで管理メニュー。上の「管理ツール」を参照） |
| `/pvp menu` | 管理メニュー（GUI）を開く（参加中でも可） |
| `/pvp reload` | `config.yml` を読み直す（地点・看板・CPU道場の段位・各設定） |
| `/pvp stop` | 進行中の試合を強制終了し、選手を元の場所へ戻す（賭け金は払い戻し）。CPU道場の挑戦中なら挑戦を止める（突破済みの段位は記録・挑戦者はロビーへ戻りメニューが開く） |
| `/pvp ranking reset <プレイヤー\|all>` | CPU道場の記録を消す（コンソールからも可） |
| `/pvp lobbyfix <プレイヤー> [force]` | ロビー入場前の持ち物が戻らないときの復旧コマンド。退避データを本人へ戻してロックを解除する（`force` を付けると退避データを破棄してロックだけ解除）。対象はオンラインである必要あり（統合版の「.」付き名も検索） |
| `/pvp setrank <名前> <ランク>` | プレイヤーのバトルパスランクを設定する（1〜10に丸められる） |
| `/pvp ranklist` | 全プレイヤーのバトルパスランク一覧を表示する |
| `/pvp setspawn <1\|2>` | 対戦開始地点を設定する（実行時の立ち位置） |
| `/pvp setchest` | 視線の先のチェストを装備リセット対象として登録する（複数可） |
| `/pvp setspectate` / `setlobby` | 観戦場所／ロビーを設定する（実行時の立ち位置） |
| `/pvp setstartspawn` | 初期スポーン（離脱・試合終了時の戻り先）を設定する（実行時の立ち位置） |
| `/pvp setsign <join\|leave\|bet\|start <識別子>\|spectate\|lobby\|solo>` | 視線の先の看板を指定種別のPvP看板として登録する（各サブコマンドは上の「看板の登録」を参照） |
| `/pvp setsign delete` | 視線の先の看板の登録を解除する |

!!! note "試合の進行は看板または手動コマンドで行います"
    キューが2人そろっても試合は自動では始まりません。`[PvP開始]` 看板（`/pvp setsign start <識別子>` で登録）を右クリックするか、`/pvp start` を実行する必要があります（`/pvp start` は全員実行可）。異常時はOPが `/pvp stop` で強制終了でき、賭け金は全額払い戻されます。なお開始看板の登録は **`/pvp setsign start <識別子>`** で行い、解除は **`/pvp setsign delete`** です。

!!! note "CPU道場の運用メモ"
    - アリーナは通常戦と共用です（開始地点1＝挑戦者、開始地点2＝CPU）。どちらかが使用中のときは、もう一方の開始を拒否して理由を表示します。
    - CPU はプラグインが出したゾンビ／ハスクで、挑戦者だけを狙います。燃えない・ドロップしない・援軍を呼ばない・保存されない設定です。サーバー停止などで残った CPU は、次回起動時やチャンク読み込み時に自動で消えます。
    - `/pvp status` に「CPU道場（ソロ）」の欄（段位数・ソロ在籍・挑戦中・記録件数）が出ます。

## 権限ノード

`plugin.yml` で定義されている権限ノードは1つだけです。

| 権限 | デフォルト | 説明 |
|---|---|---|
| `1vs1.admin` | `op` | セットアップ・管理系サブコマンド（stop/setrank/ranklist/setspawn・setchest・setsign 等）の実行権限。OPに自動付与されます。 |

!!! note "プレイヤー用コマンドは全員が使えます"
    `/pvp join`・`leave`・`spectate`・`lobby`・`bet`・`start`・`status` は **権限不要で全プレイヤーが実行可能** です（看板の右クリックと同じ動作）。看板を設置していれば看板からでも、コマンドからでも操作できます。`1vs1.admin` が必要なのは会場設定・ランク管理・試合の強制終了などのコマンドだけです。

## トラブルシューティング

??? failure "`/pvp start` で試合が始まらない"
    主な原因は2つです。1つ目は待機キューの人数不足（最低2人必要）。`[PvP参加]` 看板の2行目に「待機: N人」（現在のキュー人数）が表示され、2人以上そろうと `[PvP開始]` 看板の2行目が「開始可能」に変わるので、看板で確認してください。2つ目は開始地点の未設定です。`/pvp setspawn 1` と `/pvp setspawn 2` を実行済みか確認してください。地点未設定の場合、キューのプレイヤーはキューに戻されます。

??? failure "試合後にチェストがリセットされない"
    キットチェストが未設定か、設定した位置のブロックがチェストでなくなっている可能性があります。`/pvp setchest` を実行し直してください。未設定・非チェストの場合はサーバーログに警告（`[1vs1] キットチェスト... が設定されていません`）が出ます。

??? failure "CPU道場が始められない（開始ボタンがバリアになる）"
    ソロメニューの開始ボタンに理由が出ます。「開始地点が未設定」なら `/pvp setspawn 1`・`2`、「通常の対戦が使用中」「○○が挑戦中」なら終わるまで待ちます。「段位が設定されていません」は `config.yml` の `dojo-stages` が空か消えています（`config.yml.bak-日時` から戻せます）。

??? failure "CPU の頭がプレイヤーの顔にならない"
    `head` に指定した名前の見た目は、起動時にインターネットから取得します。取得できない名前・通信できない環境では普通の頭になります（コンソールに警告）。統合版では見た目が普通の頭になることがあります。

??? failure "`/pvp setchest` が「チェストを置いてください」と出る"
    視線の先5ブロック以内にチェストが必要です。チェストをまっすぐ見た状態でコマンドを実行してください。距離が遠い・別のブロックを見ているときは失敗します。

??? failure "プレイヤーのランクを直したい"
    `/pvp setrank <プレイヤー名> <ランク>` で個別に設定できます。指定値は自動的に1〜10の範囲に丸められます。対象プレイヤーはオンラインである必要があります。

??? failure "ランクデータが消えた／引き継がれない"
    ランクは `plugins/1vs1/ranks.yml` に保存され、サーバー停止時に書き込まれます。サーバーがクラッシュで異常終了すると直近の変更が保存されない場合があります。ファイルを削除すると全プレイヤーのランクが初期化（R3扱い）されます。
